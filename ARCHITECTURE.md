# Архитектура

Документ объясняет, **почему** решения приняты именно такие. Пользовательская документация — в [README.md](README.md).

---

## 1. Общая схема

```
┌────────────────────────┐   сообщения    ┌───────────────────────────┐
│  content script        │ ─────────────► │  service worker (MV3)     │
│  (на странице)         │ ◄───────────── │  (маршрутизатор)          │
│                        │                │                           │
│  extract → apply       │                │  translateSegments()      │
│  panel, selection, PDF │                │   ├─ IndexedDB cache      │
└────────────────────────┘                │   ├─ provider adapter     │
                                          │   └─ skill prompt         │
┌────────────────────────┐                └───────────────────────────┘
│  popup / options /     │   сообщения            │
│  print (страницы)      │ ───────────────────────┘
└────────────────────────┘                        ▼
                                            внешний API
```

**Почему так.** Service worker в MV3 засыпает через ~30 секунд простоя. Если бы долгий
перевод жил в воркере, он бы прерывался. Поэтому:

- задача перевода живёт **в контент-скрипте** (он не засыпает, пока открыта страница);
- воркер — тонкий маршрутизатор: он владеет ключами, кэшем и HTTP, но не состоянием задачи;
- состояние страницы дублируется в `chrome.storage.session`, чтобы попап мог показывать
  прогресс без опроса страницы.

## 2. Навык перевода

`src/core/skill/translation-skill.ts` — единственный источник инструкций для модели.

**Почему отдельный модуль, а не строка в адаптере.** Требование «навык, в котором указано,
что перевод с учётом контекста» означает, что инструкция — часть продукта, а не деталь
реализации. Её можно посмотреть, отредактировать, заменить и версионировать.

Состав навыка:

1. **CORE_RULES** — неизменяемые правила: что не переводить, как учитывать контекст, формат
   ответа `[id] текст`.
2. **DOMAIN_GUIDE** — подсказка регистра для 8 типов документов. Домен определяется
   эвристикой `detectDomain()` по хосту, заголовку и плотности кода.
3. **GLOSSARY** — термины пользователя, отфильтрованные по сайту.
4. **Стиль и дополнительная инструкция** — из настроек.

`SKILL_VERSION` входит в ключ кэша, поэтому изменение промпта автоматически инвалидирует
ранее сохранённые переводы.

**Почему `[id] текст`, а не JSON.** Модели гораздо чаще ломают JSON (экранирование,
обрывы), чем плоский список блоков. Парсер `parseAnswer()` терпим к обёрткам вида
```` ``` ````, вступлению перед первым блоком и примечанию после последнего.

### Валидатор

`src/core/skill/validate.ts` проверяет три вещи:

1. **Полнота** — каждый запрошенный `id` присутствует ровно один раз.
2. **Слоты** — `{{n}}` и `{{/n}}` сбалансированы и не выдуманы.
3. **Защищённые токены** — URL, инлайн-код, плейсхолдеры, имена файлов не потеряны.

Если проверка не прошла, вызывающий код **не применяет** ответ к странице: делается до двух
попыток починки, затем проблемные фрагменты остаются оригинальными, а в панели появляется
пометка «часть фрагментов не переведена». Страница никогда не остаётся сломанной.

## 3. Слоты — как сохраняются ссылки и код

Наивный подход «склеить текст абзаца и заменить его» уничтожает ссылки: `<a href="/x">док</a>`
превращается в текст. Поэтому:

```
исходный DOM:  Read the <a href="/x">guide</a> and call <code>fn()</code>.
промпт:        Read the {{0}}guide{{/0}} and call {{1}}{{/1}}.
ответ модели:  Прочитайте {{0}}руководство{{/0}} и вызовите {{1}}{{/1}}.
итоговый DOM:  Прочитайте <a href="/x">руководство</a> и вызовите <code>fn()</code>.
```

- **Переводимые слоты** (`a`, `abbr`, `sub`, `sup`, `button`) — клон элемента, содержимое
  берётся из ответа модели.
- **Непрозрачные слоты** (`code`, `kbd`, `samp`, `var`, `img`, `svg`) — содержимое вообще не
  отправляется модели и восстанавливается из оригинала байт-в-байт.

Рендер `renderTranslation()` поддерживает вложенность и не падает на несбалансированном
маркере — проверка слотом всё равно отбракует такой ответ раньше.

## 4. Извлечение текста

`src/content/extract.ts`. Правила:

| Что | Решение |
|---|---|
| Блоки | один сегмент на ближайший блочный предок (`p`, `li`, `h2`, `div`, …) — модель видит целое предложение |
| Инлайн | `a`, `strong`, `em` не разрывают предложение, а становятся слотами |
| Код | `pre`, `code` не попадают в промпт; комментарии — только при включённой настройке |
| Служебное | `script`, `style`, `noscript`, `svg`, `math`, `input`, `textarea`, `[hidden]`, `[aria-hidden="true"]` |
| Обвязка | `nav`, `footer`, `aside`, cookie-баннеры — при включённой настройке |
| Своё | `[data-lingo-ignore]`, `.lingo-panel`, `.lingo-bubble` — чтобы расширение не переводило само себя |
| Атрибуты | `alt`, `title`, `placeholder`, `aria-label` — по настройке, только если текст не похож на код |
| Мусор | сегменты без букв, короче двух символов, чистая пунктуация |

**Почему без видимости во вьюпорте.** Ранняя версия переводила только видимую область и
ошибалась: страница оставалась переведённой наполовину. Теперь переводится документ целиком,
а прогресс показывается порциями; для очень длинных страниц работает ограничение
`chunkSize` и кнопка «Остановить».

## 5. Подстановка и откат

`src/content/apply.ts`:

- блок заменяется на `<span data-lingo="translation">…</span>`, оригинальные дочерние узлы
  сохраняются в памяти;
- при `keepOriginal` рядом добавляется `<span class="lingo-original-text">`;
- переключение «Оригинал» — это класс на `<html>`, без перерисовки и повторных запросов;
- `revertBlocks()` возвращает узлы на место, поэтому DOM восстанавливается **побайтово**
  (это проверяется тестом).

## 6. Провайдеры

`src/core/providers/`:

| Файл | Что внутри |
|---|---|
| `types.ts` | интерфейс адаптера, ключ кэша, отпечаток глоссария |
| `http.ts` | таймауты, отмена, ретраи с backoff, единая карта ошибок |
| `llm.ts` | общий конвейер модели: навык → промпт → валидация → починка |
| `openai.ts` | OpenAI-совместимые: DeepSeek, OpenAI, OpenRouter, Groq, Ollama, свой шлюз |
| `anthropic.ts` | Messages API |
| `gemini.ts` | generateContent |
| `mt.ts` | Google без ключа, MyMemory, LibreTranslate, Lingva, DeepL Free |
| `pool.ts` | ограничение параллельности, разбиение по бюджету символов |

**Почему один адаптер на все OpenAI-совместимые API.** Они отличаются только базовым URL,
моделью и парой заголовков. Дублировать код на каждый сервис — источник расхождений.

**Почему бесплатные сервисы обрабатывают сегменты по одному.** У них нет понятия контекста,
и склеивать абзацы ради экономии запросов бессмысленно: качество не вырастет, а лимиты
можно упереть быстрее.

**Защита кода в бесплатных сервисах.** Перед отправкой инлайн-код и токены заменяются
маркерами `\u0001n\u0001` и восстанавливаются после ответа — так даже контекстно-независимый
сервис не портит идентификаторы.

## 7. Кэш

`src/core/cache.ts` (IndexedDB, store `translations`).

Ключ: `v<SKILL_VERSION> | provider | model | sourceLang | targetLang | glossaryHash | text`.

- разные модели и языки не пересекаются;
- изменение глоссария или навыка инвалидирует записи;
- TTL настраивается, есть очистка и подсчёт объёма.

**Почему IndexedDB, а не `chrome.storage`.** `storage` рассчитан на мегабайты и сериализует
весь объект при записи; кэш переводов быстро перерастает эти пределы.

## 8. Определение языка

`src/core/lang-detect.ts`:

1. если браузер предоставляет `LanguageDetector`, используется он;
2. иначе — подсчёт письменности: кириллица отделяется от латиницы, CJK различается по
   кане и Han, украинский/белорусский — по характерным буквам;
3. латиница различается по стоп-словам 20 языков.

Определение выполняется **один раз на страницу** по выборке из 30 первых сегментов, а не на
каждое предложение: смешанные страницы иначе определяются хаотично.

## 9. PDF

`src/content/print.ts` собирает `PrintPayload`, service worker сохраняет его в
`chrome.storage.session` и открывает `print.html` — отдельную страницу расширения.

**Почему не `chrome.debugger` + `Page.printToPDF`.** Этот путь даёт одну кнопку без диалога,
но требует разрешения `debugger` и показывает пользователю баннер «Chrome управляется
автоматизированным ПО». Для расширения, которое ставится ещё и в Яндекс Браузер и Opera,
это неприемлемо. Диалог печати работает везде одинаково и не требует разрешений.

**Почему payload через session storage, а не в URL.** У `data:`/blob-URL есть ограничения
длины, а страница расширения не должна получать данные из непроверенного источника.

## 10. Сборка

`scripts/build.mjs` — самодостаточный сборщик на компиляторе TypeScript:

1. обходит граф модулей от точек входа;
2. транспилирует каждый модуль в CommonJS;
3. заворачивает их в реестр модулей и отдаёт один классический скрипт на точку входа.

**Почему не esbuild/webpack.** В среде разработки запрещён запуск дочерних процессов, а
esbuild запускает сервис отдельным процессом. Свой сборщик работает везде, где есть Node и
`typescript`, и даёт ровно то, что нужно расширению.

Ограничение осознанное: поддерживаются только относительные импорты. Для проекта без
runtime-зависимостей это не ограничение, а гарантия, что в бандл не попадёт лишнего.

## 11. Тестирование

| Уровень | Инструмент | Что ловит |
|---|---|---|
| Юнит | `scripts/test.mjs` (свой раннер) | логика навыка, валидатора, извлечения, кэша, настроек |
| Бандл | `tools/bundle-e2e.mjs` | собранный service worker + мок `chrome` + живой HTTP-мок DeepSeek |
| Страница | `tools/dom-e2e.mjs` | реальный HTML `book.leptos.dev` в jsdom: извлечение, слоты, применение, откат |
| UI | `tools/ui-smoke.mjs` | попап и все вкладки настроек в jsdom |
| Кодировка | `scripts/check-encoding.mjs` + тест | «кракозябры» в русских строках |

**Почему нет Playwright.** Браузер нельзя запустить из песочницы. Вместо имитации браузера
проверяется настоящий бандл в Node с мок-API Chrome и настоящая страница в jsdom — это
покрывает всё, кроме рендеринга, который jsdom выполняет достаточно точно для DOM-логики.

## 12. Известные компромиссы

| Компромисс | Причина | Что можно улучшить |
|---|---|---|
| Нет перевода при прокрутке | сложность и риск бесконечных затрат | `MutationObserver` по кнопке |
| Бесплатные сервисы без контекста | у них нет API контекста | — |
| PDF через диалог печати | совместимость и отсутствие разрешений | опциональный режим через `debugger` |
| Бандл без code-splitting | размер 75–110 КБ некритичен | ленивые чанки для options |
| Свой тест-раннер | запрет на дочерние процессы | vitest при первой возможности |

## 13. Куда добавлять новое

**Новый LLM-провайдер с OpenAI-совместимым API** — запись в `PROVIDERS` (`shared/providers.ts`)
и один вызов `makeOpenAiAdapter(id)` в `providers/index.ts`. Больше ничего.

**Новый сервис машинного перевода** — адаптер в `providers/mt.ts` (образец: `googleFreeAdapter`)
и запись в каталоге.

**Новое правило навыка** — правка `CORE_RULES`, затем поднять `SKILL_VERSION` в
`skill/version.ts`, чтобы кэш не отдавал старые переводы.

**Новое правило извлечения** — `extract.ts` (`SLOT_TAGS`, `SKIP_TAGS`, `BLOCK_TAGS`) плюс
тест в `tests/extract.test.ts`.
