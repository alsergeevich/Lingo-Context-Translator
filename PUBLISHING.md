# Как опубликовать расширение

Расширение ставится тремя способами. Только публикация в магазине решает **проблему 2**
(Яндекс Браузер отключает расширения не из магазина при каждом перезапуске) — установка
из папки этого не даёт никогда, сколько бы настроек ни меняли.

| Способ | Нужен аккаунт | Проверка | Перезапуск Яндекса | Обновления |
|---|---|---|---|---|
| Загрузить распакованное (`dist/`) | нет | нет | **отключается каждый раз** | вручную |
| Chrome Web Store | Google + $5 + 2FA | 1–3 дня | работает | автоматически |
| Opera Add-ons | Opera-аккаунт, бесплатно | от часов до недель | работает | автоматически |

Yandex пишет прямо: «В целях безопасности расширение будет работать до закрытия Yandex
Browser. При каждом перезапуске… придётся включать его заново. Чтобы этого избежать,
обратитесь к разработчикам с просьбой опубликовать его в Chrome Web Store или Opera
Add-ons» ([browser.yandex.ru/help](https://browser.yandex.ru/help/ru/security/check-extensions.html)).
Проверка включена только на Windows; в бета-версии Яндекса её нет.

## Что уже готово в репозитории

```
npm run release        # build + package → release/lingo-context-0.1.3.zip
```

- `public/manifest.json` — MV3, `default_locale: ru`, иконки 16/32/48/128 (настоящие PNG,
  не переименованные), 3 команды, `options_ui.open_in_tab: true`.
- `release/lingo-context-0.1.3.zip` — `manifest.json` лежит **в корне архива** (проверено:
  `unzip -l`), 18 файлов, все ссылки из манифеста существуют.
- Бандлы **не минифицированы**: читаемый вывод с комментариями, ни одной строки длиннее
  400 символов. Это требование Opera и рекомендация Chrome Web Store.
- Нет удалённого кода, нет `eval`, нет инлайновых скриптов в HTML — политика MV3 соблюдена.
- Тексты магазина: `public/_locales/ru/messages.json` (extName 22 символа, extDescription
  117) и `en` (24 / 121). Лимиты магазина — 75 и 132, запас большой.
- `PRIVACY.md` — политика конфиденциальности на двух языках, её можно взять как есть.
- `store/` — готовые материалы для карточки:

| Файл | Размер | Куда |
|---|---|---|
| `store/icon-128.png` | 128×128 | иконка магазина |
| `store/screenshot-1-popup.png` | 1280×800 | скриншот 1 (попап) |
| `store/screenshot-2-before-after.png` | 1280×800 | скриншот 2 (до/после) |

## Чего не хватает перед загрузкой

1. **Публичная ссылка на политику конфиденциальности.** `PRIVACY.md` лежит в репозитории —
   магазину нужен URL. Варианты: GitHub Pages, страница на своём сайте, gist. Chrome
   требует публичный URL, файл в приватном репозитории не подойдёт.
2. **Скриншот 5-го типа (необязательно)** — Opera любит карточку с описанием возможностей;
   лимит Chrome — 5 скриншотов, у нас 4.
3. **Промо-изображение 440×280 (Chrome, необязательно)** — если хочется выделенную карточку.

Загружать нужно **только** `release/lingo-context-*.zip`: в нём `manifest.json` лежит в корне
архива. Собранная папка `dist/` для загрузки не подходит — магазин принимает архив, а не
каталог, и любой zip с файлами под префиксом (`dist/manifest.json`) он отвергнет.

## Chrome Web Store

### 1. Аккаунт разработчика

1. Откройте <https://chromewebstore.google.com/devconsole> и войдите в Google-аккаунт.
2. Оплатите однократный взнос **$5** (покрывает до 20 расширений).
3. Включите **двухэтапную аутентификацию** — без неё публикация и обновления блокируются
   ([требование](https://developer.chrome.com/docs/webstore/program-policies/two-step-verification)).
4. Заполните имя публикатора и контактный e-mail, подтвердите его.

### 2. Первая загрузка — только руками

API магазина **не умеет создавать новый товар**, поэтому первый раз — через
<https://chromewebstore.google.com/devconsole> → **New item** → загрузить
`release/lingo-context-0.1.3.zip`. После этой загрузки появляется 32-символьный ID
расширения, и только тогда можно пользоваться [Chrome Web Store API](https://developer.chrome.com/docs/webstore/using-api)
для автоматизации следующих версий.

### 3. Карточка товара

- **Название** — до 75 символов, без «Chrome» и без чужих брендов.
- **Описание** — до 132 символов в кратком поле; полное описание — в магазине.
- **Категория** — «Продуктивность» / «Инструменты разработчика».
- **Иконка** — `store/icon-128.png`.
- **Скриншоты** — 1280×800, от одного до пяти; наши четыре подходят как есть.
- **Языки** — ru (основной) и en; манифест уже отдаёт оба через `_locales`.
- **Политика конфиденциальности** — публичный URL на текст из `PRIVACY.md`.

### 4. Обоснование разрешений (Review justification)

Ревьюер читает это поле. Готовый текст:

> `storage` — хранит настройки, API-ключи пользователя и кэш переводов локально; ничего не
> отправляется на наши серверы. `activeTab` + `host_permissions` на `http://*/*`,
> `https://*/*` — расширение переводит произвольную страницу по нажатию кнопки, поэтому
> список сайтов заранее неизвестен; скрипт ничего не делает, пока пользователь не нажал
> «Перевести». `scripting` — повторно внедряет контент-скрипт, если вкладка была открыта до
> установки расширения. `contextMenus` — пункты «Перевести страницу», «Перевести
> выделенное», «Сохранить в PDF». `host_permissions` на адреса API — прямые запросы к
> выбранному пользователем сервису перевода; собственного бэкенда нет.
> `optional_host_permissions` — для собственного шлюза, который пользователь может указать.

**Важно про `http://*/*` и `https://*/*`.** Они указаны одновременно в
`content_scripts.matches` и в `optional_host_permissions`. Первое даёт доступ ко всем сайтам
(и это неизбежно: страницу для перевода выбирает пользователь), второе нужно, чтобы
`chrome.permissions.request()` мог запросить произвольный адрес собственного шлюза —
Chromium разрешает запрашивать только те origin'ы, которые перечислены в
`optional_host_permissions`. Убирать их нельзя, иначе «Свой OpenAI-совместимый API»
перестанет работать. В обосновании так и напишите: «optional_host_permissions нужны для
собственного шлюза, который пользователь вводит сам; запрос выдаётся только на этот origin и
только по действию пользователя».

### 5. Публикация

Отправка → проверка (обычно 1–3 дня, при изменениях разрешений дольше) → статус
**Published**. Замечания приходят на e-mail публикатора; исправленная версия загружается с
**бóльшим** номером (0.1.4, 0.1.5 …), повторная загрузка той же версии отклоняется.

## Лимиты полей манифеста (частая причина отказа)

Магазин проверяет **сырой** `manifest.json`, до подстановки `__MSG_*__`, и на слишком длинном
поле отвечает так:

```
manifest.json is invalid. … The parser reported: 'Lingo Context' is too long
```

Это ровно то, что случилось с 0.1.2: в `short_name` стояло 13 символов при лимите 12. Поэтому
`short_name` теперь литерал `"Lingo"` (5 символов), а не ключ локализации — ключ
`__MSG_extShortName__` формально короткий, но проверять его длину бессмысленно, а магазин
смотрит именно на сырое значение. Имя и описание по-прежнему берутся из `_locales`.

| Поле | Предел | Сейчас |
|---|---|---|
| `short_name` | 12 | `Lingo` — 5 |
| `name` (подставленное) | 75 | 22 (`ru`) / 24 (`en`) |
| `description` (подставленная) | 132 | 117 (`ru`) / 121 (`en`) |
| `version` | 4 числа, каждое ≤ 65535 | `0.1.3` |

Всё это закреплено тестом `tests/manifest.test.ts → keeps store-visible strings inside the
store limits`, так что повторно наступить на те же грабли не получится.

## Opera Add-ons

1. Заведите аккаунт на <https://addons.opera.com/developer/>.
2. **Submit an extension** → загрузите тот же `release/lingo-context-0.1.3.zip`.
3. Заполните карточку (название, описание, категория, иконка, скриншоты) и **укажите ссылку
   на исходный код или на неманифицированную сборку** — Opera отклоняет минифицированный
   код, если нельзя посмотреть исходники. У нас бандлы и так читаемые, но ссылка на
   репозиторий снимает вопрос совсем.
4. Отправьте на модерацию (может занять от нескольких часов до недель).

Частые причины отказа по [критериям Opera](https://maqentaer.github.io/operaextensions.js/docs/articles/opera-extension-publishing-guidelines/extensions-publishing-guidelines.html):
минифицированный или запутанный код, удалённый JavaScript, лишние разрешения, «Opera» в
названии, неиспользуемые файлы, реклама. MV2 больше не принимают — у нас MV3.

После одобрения Opera сама прописывает в установленный манифест
`"update_url": "https://extension-updates.opera.com/api/omaha/update/"`; вручную его
добавлять не нужно и вредно.

## Яндекс Браузер

Отдельной публикации не требуется: Яндекс считает «доверенным» то, что пришло из Chrome Web
Store или Opera Add-ons, и перестаёт отключать расширение при перезапуске. Что важно:

- Установка из папки (`Загрузить распакованное`) остаётся «неизвестным источником» навсегда
  — отключение при каждом старте это ожидаемое поведение, а не баг расширения.
- Пока расширение не в магазине, для разработки используйте
  [бета-версию Яндекса](https://browser.yandex.com/beta/) — в ней проверки расширений нет.
- Для корпоративного развёртывания политика `ExtensionInstallForcelist` принимает только
  адреса магазинов: `https://clients2.google.com/service/update2/crx/` (Chrome Web Store) или
  `https://extension-updates.opera.com/api/omaha/update/` (Opera).

## Про ID расширения и потерю настроек

У распакованного расширения ID вычисляется из **пути к папке** (`dist/` в этом репозитории
даёт `pegkbcbalejannphnlfkileodfeffkao`). Переименовали папку, распаковали заново в другое
место — ID сменился, и для браузера это уже другое расширение: настройки, ключи и кэш
остались у старого ID. Отсюда и сообщения вида «расширение пропало» после переустановки.

Стабильный ID задаётся полем `"key"` в манифесте (публичный ключ, 2048-бит RSA в base64).
Добавлять его нужно **до** первой установки, иначе пользователи уже сохранены под старым ID:

```bash
# один раз: сгенерировать ключ и получить из него ID
openssl genrsa -out lingo-key.pem 2048
openssl rsa -in lingo-key.pem -pubout -outform DER | base64 -w0   # → поле "key"
```

Для магазинных сборок `key` не нужен: ID выдаёт магазин, а `update_url` он прописывает сам.

## Чек-лист перед отправкой

```bash
npm run verify        # типы, тесты, сборка, сквозные проверки, кодировка
npm run release       # соберёт dist/ и release/lingo-context-<версия>.zip
```

- [ ] Версия в `public/manifest.json` больше, чем в предыдущей загрузке.
- [ ] `unzip -l release/lingo-context-*.zip | head` — `manifest.json` в корне, без префикса.
- [ ] В архиве нет `tests/`, `src/`, `node_modules/`, `.map`-файлов.
- [ ] Публичный URL политики конфиденциальности открывается в приватном окне.
- [ ] Скриншоты 1280×800 (или 640×400), иконка 128×128.
- [ ] Обоснование разрешений заполнено (текст выше).
- [ ] В названии и описании нет «Chrome», «Opera», «Yandex» как части бренда.
- [ ] `short_name` ≤ 12 символов (Opera проверяет сырое значение, до подстановки `__MSG_*__`).
- [ ] В репозитории есть `LICENSE` и он виден в карточке — его спрашивают при ревью.
